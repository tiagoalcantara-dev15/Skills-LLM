# Traducao e localizacao (i18n)

Padroes do Fluxo para traducao, formatacao de data, numero, moeda e parse de entrada localizada. Use ao implementar e ao revisar qualquer mudanca que altere o que o usuario le, digita ou ve formatado na tela.

Se o repo tiver `wikiMigration_PT_BR/padroesI18nELocalizacao.md`, leia-o em casos incomuns ou quando precisar do guia completo.

## Checklist

Verifique se a mudanca toca:

- texto visivel ao usuario
- placeholders, labels, botoes, abas, titulos, captions
- mensagens de validacao e notificacoes
- datas exibidas na UI ou enviadas ao backend
- numeros, percentuais, moedas, totais
- parse de entrada localizada

Se nada disso for tocado, esta referencia nao se aplica.

## Padrao de traducao

| Contexto | Uso |
|----------|-----|
| Blade | `{{ __('Texto aqui') }}`; em atributos: `placeholder="{{ __('Texto aqui') }}"`, `title="{{ __('Texto aqui') }}"` |
| Blade com short tag PHP | `<?= __('Texto aqui') ?>` |
| PHP backend | `__('Texto aqui')` (titulo de modal, caption de grid, mensagem de validacao, label devolvido como dado de UI) |
| JavaScript | `LangFluxo.get('Texto aqui')` (placeholder, notificacao, validacao, botao dinamico, template renderizado em JS) |
| React | `window.LangFluxo.get('Texto aqui')` |

## Fontes de traducao

Com chave de texto livre (`__('Nome')`):

- a chave e o proprio texto PT-BR: nao existe `pt_BR.json`. Adicione a traducao em cada `resources/lang/{locale}.json` (`en_US`, `es_CL`, `fr_FR`; ver `fluxo-arquitetura`).

Com `LangFluxo.get(...)`:

- adicione a frase exata na fonte JSON ou PHP de idioma;
- adicione a frase em `resources/lang/js/lang.php`:

```php
$strings[] = 'Campo obrigatório';
```

Quando o codigo ja usa chaves estruturadas (`__('sim_nao.S')`, `__('entrada_saida.E')`):

- preserve o padrao;
- atualize o `resources/lang/<locale>/<arquivo>.php` correspondente.

Nao converta um dominio de chaves estruturadas para texto livre so por consistencia.

## Datas

PHP / Blade:

```php
AllStrategy_Date::getLocalizationStringFormatDateDefault('date')
```

Variantes: `'date'`, `'datetime'`, `'time'`. Exemplo: `'format' => AllStrategy_Date::getLocalizationStringFormatDateDefault('date')`.

JavaScript:

```js
displayFormat: getLocalizationStringFormatDateDefault('date')
```

Conversao: ao ler valor de componente ou montar payload, use `convertDataFormat(value)` entre `DateBox`/`DateRangeBox`, estado JS, AJAX e a string de data esperada pelo backend.

## Numero, percentual e moeda

| Necessidade | PHP | JS |
|-------------|-----|----|
| Decimal | `formatLocalizedValue($value, 2)` | `formatLocalizedValue(value, 2)` |
| Moeda | `formatLocalizedValue($value, 2, true, NumberFormatter::CURRENCY)` | `formatLocalizedValue(value, 2, true, LocalizationService.CURRENCY)` |
| Moeda forcada | acrescente `, 'USD'` ao final | acrescente `, 'USD'` ao final |
| Percentual | — | `formatLocalizedValue(value, 2, true, LocalizationService.PERCENT)` |
| Parse de entrada | `unformatLocalizedValue($value)` | `unformatLocalizedValue(value)` |

Configuracao em JS:

- AutoNumeric: `getLocalizedAutoNumericConfig({...})`
- Highcharts: `Highcharts.setOptions(getLocalizedHighchartsSetOptions({...}))`

## Padroes especificos de componente

Se uma biblioteca de UI exige string de formato na configuracao, mantenha o estilo compativel com o componente ja usado no projeto.

- Colunas de data do DevExpress: `AllStrategy_Date::getLocalizationStringFormatDateDefault('date')`
- Inputs de data do DevExpress: `getLocalizationStringFormatDateDefault('date')`
- Colunas de grid que exigem mascara numerica ainda podem usar config do componente, como `#,##0.00`

Mesmo nesses casos:

- nao adicione `toLocaleString('pt-BR')`
- nao adicione `number_format(...)` para saida de exibicao
- nao fixe locale em codigo novo

## Anti-padroes

Nao introduza:

- texto de UI sem traducao em Blade, PHP, JS ou React
- `toLocaleString('pt-BR')`
- `number_format(...)` para valor exibido na UI
- mascara de data fixa quando ja existe helper de localizacao
- comparacao direta com texto traduzido (`"Sim"`, `"Não"`, `"Selecione ..."`)
- logica que dependa do texto exibido em vez de codigos ou IDs estaveis

Se encontrar anti-padrao existente por perto, alinhe o codigo novo ao padrao e aponte a limpeza maior separadamente.

## Conferencia final

- todo texto visivel passa por `__()` ou `LangFluxo.get()`
- toda frase nova usada em JS esta em `resources/lang/js/lang.php`
- toda frase traduzida nova existe na fonte de idioma correta
- datas usam o helper de localizacao, nao mascara fixa
- saida numerica e de moeda usa `formatLocalizedValue(...)`
- parse numerico localizado usa `unformatLocalizedValue(...)`
- nenhum locale fixo novo
- nenhuma logica nova depende de texto traduzido
